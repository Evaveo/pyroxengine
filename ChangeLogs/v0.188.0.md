# v0.188.0 — Atelier Blender : le moteur parle directement à Blender

## Ajouté

- **Fenêtres → 🧱 Atelier Blender.** Un panneau manuel, sans IA : connexion à Blender, envoi de
  concept arts (posés en images de référence) ou de modèles, rendu quatre vues, atlas PBR, et
  **Exporter et importer dans le projet** — le GLB arrive comme un glisser-déposer (matériaux,
  clips en sous-assets). Il propose aussi le téléchargement de l'addon et ses trois étapes
  d'installation.
- **⚡ Installer et ouvrir Blender**, dans l'Atelier : l'éditeur fabrique un petit script (.cmd sous
  Windows, .sh sous macOS/Linux) à ouvrir d'un double-clic. Il trouve Blender, installe l'addon
  depuis l'éditeur, y pose le jeton et l'origine de la page (plus rien à copier-coller), enregistre
  le lien `evaveo-blender://` (Windows : profil utilisateur, sans droits administrateur ; Linux :
  xdg-mime), puis ouvre Blender — l'Atelier se connecte seul. Ensuite, **▶ Ouvrir Blender** lance
  Blender depuis l'éditeur. Tant que Blender est fermé, l'Atelier ne le sonde plus que toutes les
  30 s (3 s juste après « Installer » ou « Ouvrir »).
- **Addon Blender « EVAVEO Blender Bridge »** (Blender 4.5 LTS ou plus récent), livré par le moteur
  (`exemples/blender/evaveo_blender_bridge.zip`, sources sous `outils/blender-addon/`). Il tient un
  petit serveur HTTP sur 127.0.0.1:9877 et exécute le pipeline repris d'EVAVEO Asset Pipeline 0.2 :
  modélisation libre (mesh, sweep, lathe, extrusion, modificateurs), PBR, UV, rig, animation,
  atlas, export GLB avec LOD et collisions, rendus.
- **Commandes MCP `blender_*`** : `blender_status`, `blender_scene`, `blender_project`,
  `blender_geometry`, `blender_material`, `blender_uv`, `blender_rig`, `blender_animation`,
  `blender_inspect`, `blender_import`, `blender_delivery`, `blender_preview` (renvoie l'image) et
  `blender_import_to_project`. Elles passent par le MCP cloud **et** le pont local, sans rien à
  configurer de plus : une IA (Claude Desktop, Claude Code…) modélise dans Blender. La méthode lui
  est servie en ressource `editeur3d://guide/blender`. Pour le copilote intégré, elles sont dans le
  domaine `blender` (`load_tools`).
- **Copilote, fournisseur OpenAI** : la liste des modèles propose les derniers sortis —
  `gpt-6-astra`, `gpt-5.6` (Sol), `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`, `gpt-5.5-pro`. Pour gpt-5.6 et gpt-6, le copilote envoie
  `reasoning_effort: 'none'` : sans ça, l'API refuse les outils (erreur 400) sur `/v1/chat/completions`.
- **Guide `editeur3d://guide/blender` : « Modéliser proprement ».** Moitié + modificateur MIRROR,
  retoucher l'existant au lieu de tout refaire, souder les pièces (join + cleanup, BOOLEAN UNION)
  plutôt qu'empiler des primitives, découper selon ce que le jeu anime, et livrer JOUABLE : prefab
  branché dans le code de gameplay, vérifié par `play_and_measure`. Toujours retoucher la dernière
  version (jamais restaurer un ancien checkpoint ni supprimer une pièce validée sans demande), garder
  séparées les pièces critiquées, ne pas importer avant validation. Rappel dans la description de
  `blender_project restore` et dans le README de l'addon.
- **Addon Blender 1.4.0 : `blender_animation clip` remplace un clip du même nom** au lieu d'en créer
  un second (l'aperçu jouait l'ancien, l'export livrait les deux), et **`delete:{object,name}`**
  supprime un clip et son action.
- **`move_asset` ne range plus le mauvais homonyme.** Il prenait le premier asset du nom : ranger la
  donnée « Decor » déplaçait le script « Decor ». Ambigu ⇒ refus qui liste genre et dossier ;
  nouveaux paramètres `kind`, `from` (dossier actuel) et `all`. `delete_asset` accepte aussi `kind`.
- **`audit_project` signale une classe d'état figée dans un document UI.** Une classe comme `off`
  écrite en dur sur un élément qui porte aussi `data-bind-class` ne part jamais : le moteur garde la
  classe du HTML et y ajoute la valeur liée (`invite off` + « on » → `invite off on`, toujours caché).
  Le HUD de Zeldo n'a jamais affiché son invite ni ses dialogues à cause de ça, sans rien en console.

## Supprimé

- **Le plugin « EVAVEO 3D Studio »** et le paquet du Studio. Il fallait installer Python, uvx,
  blender-mcp et deux addons, lancer un `.bat`, coller un jeton qui changeait à chaque lancement,
  et payer une IA OpenAI. Il ne reste qu'un addon Blender. Un projet où le plugin est encore
  installé le signale dans la Console.
- L'avertissement « le Studio et le pont MCP écoutent tous deux 8765 » : l'addon écoute sur 9877.

## Sécurité

- L'addon n'écoute que sur 127.0.0.1, exige un jeton (persistant, révocable), et ne répond qu'aux
  origines de sa liste blanche — l'éditeur local par défaut ; l'éditeur en ligne s'ajoute en
  collant son origine (« Autoriser l'éditeur en ligne »). Jamais `*`. Aucune route n'exécute de
  code reçu ; les fichiers lus et écrits restent confinés au dossier de travail.
- Côté moteur, `blender-link.js` est la seule porte : adresse fixe (seul le port se règle), GLB
  vérifié par sa signature avant import, 256 Mo au plus. Via le cloud, le jeton Blender ne quitte
  jamais le navigateur.
