# v0.180.0 — plugins : dans le projet, dans le jeu publié, et avec des systèmes

Passe de revue du système de plugins. L'API v2 était saine, mais aucun plugin écrit selon sa
propre documentation ne se chargeait, et un plugin restait un outil d'édition seulement.

## Added
- **Plugins du projet.** Menu Plugins → case **« Dans le projet »** : le plugin est copié dans
  `project.settings.plugins` (`[{name, code, uid}]`). Il voyage avec le projet (`.p3d`, dossier,
  cloud) et se rejoue à l'ouverture sur une autre machine, derrière la même question de confiance
  que les scripts (`js/script-trust.js`, genre `plugin`). Un plugin du même nom déjà installé
  localement avec un code différent est remplacé pour la session par la version du projet, sans
  toucher la copie locale.
- **Plugins dans le jeu publié.** Nouveau module partagé `js/plugin-host.js`, embarqué dans le
  build : le lecteur autonome rejoue les plugins du projet avant de reconstruire les scènes. Les
  composants, systèmes, types d'objets (`make`/`restore`) et matériaux (`make`, avec le même `ctx`
  que l'éditeur) y fonctionnent ; les enregistrements d'interface y sont sans effet.
  `Editor.runtime` vaut `true` dans le jeu.
- **`Editor.registerSystem({name, requires, order, onFrame})`** : un travail par image, dans la
  boucle partagée `js/systems.js` (`ctx.mode` = `'edit'` ou `'play'`). Réenregistrer remplace ;
  retirer le plugin retire le système.
- **`Editor.api.Component`** : la classe de base des composants. Sans elle, `registerComponent`
  était inutilisable depuis un plugin, qui n'a pas d'`import`.
- **Guide auteur** : `moteur/docs/PLUGINS.md`.

## Fixed (v0.177.1)
- **Les plugins reçoivent `Editor`.** Le paramètre s'appelait encore `Editeur` (reliquat du
  renommage) alors que la doc, l'exemple de la modale et `exemples/plugin-*.js` écrivent
  `Editor.register…` : chaque plugin levait un `ReferenceError` au chargement. Le harnais de test
  posait `Editor` en globale et masquait le défaut ; un test retire désormais ce pont. `Editeur`
  reste accepté comme alias.
- `registerCommandMenu` lisait `def.raccourci` au lieu de `shortcut` : le raccourci d'un plugin
  était ignoré.
- Les messages d'erreur de l'API citaient les anciens noms français (`enregistrerTypeObjet`,
  `fabriquer`, `libelle`, `nomType`).
