# v0.116.0 — les commandes du copilote passent en anglais, caméra 3D avancée

## Changé (rupture pour un client qui appelait le copilote par nom de commande)

- **Renommage de toutes les commandes du copilote en anglais** (`moteur/js/copilot.js`,
  `copilot-workshop.js`, `copilot-observer.js`) : les noms d'outils (`name` de chaque commande —
  ex. `lister_scene` → `list_scene`, `creer_objet` → `create_object`, `configurer_materiau` →
  `configure_material`…) suivaient encore la convention française, alors que `CLAUDE.md`/le
  glossaire imposent l'anglais pour tout identifiant de code — dont explicitement « les clés de
  schéma des commandes du copilote ». Seules les CLÉS DE PARAMÈTRES (`name`, `position`,
  `resolution`…) avaient été migrées jusqu'ici ; le nom de la commande elle-même ne l'avait
  jamais été, dans aucune des ~50 commandes existantes. Répercuté partout où ces noms sont cités
  en dur : `help-content.js`, `moteur/docs/API-IA.md`, `moteur/SPECIFICATIONS.md`,
  `moteur/ROADMAP.md`, les exemples (`moteur/exemples/`), les tests (`moteur/test/*.test.mjs`),
  et **`cloud/back/plans.js`** (la liste blanche de commandes du copilote SaaS côté serveur — un
  composant `cloud/` distinct, qui référence les mêmes noms). Les commentaires et messages
  utilisateur restent en français ; seuls les tokens `name` des outils ont changé.

## Ajouté

- **`configure_camera`** (`moteur/js/copilot.js`) — règle une caméra 3D en perspective : field of
  view, plans near/far, caméra principale (un seul flag actif à la fois, comme
  `js/ui/panels-components.js` le fait dans l'inspecteur) et les calques qu'elle voit
  (`userData.game.camMask`). Seule la caméra 2D avait une commande dédiée
  (`configure_camera_2d`) ; les réglages 3D restaient à la main dans l'inspecteur.
