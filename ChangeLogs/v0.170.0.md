# v0.170.0 — le multijoueur, pour de vrai

## Added
- `api.network.host()` : crée un salon sur le relais puis le rejoint (rend {code, id, authority}).
- `api.network.send(canal, données)` / `api.network.on(canal, fn)` : messages de jeu libres, relayés
  aux autres joueurs (canaux réservés `$arrival` / `$leave`). Pour les jeux où chaque joueur se
  simule chez lui (FPS rapide) plutôt que « l'autorité simule tout ».

## Fixed
- **Le multijoueur ne se connectait jamais** : la migration des noms (v0.89.1) avait traduit côté
  client les VALEURS du protocole du relais (`bienvenue` → `welcome`, `depart` → `start`,
  `autorite` → `authority`). Rejoindre ne résolvait pas, `NETWORK.me` restait nul, chacun se croyait
  autorité — le panneau Réseau de l'éditeur compris. Normalisation côté client, deux formes
  acceptées. Test : `reseau-protocole.test.mjs`.
- La partie en ligne se ferme avec le jeu (`stopGame`).

## Fixed (v0.170.2)
- `api.create` d'un prefab échouait dans le jeu publié / l'aperçu (« smoothingFromRoughness is not
  defined ») : `Mesh.serialize`, appelé par le clonage, dépendait d'une globale de materials.js,
  que le build ne charge pas.

## Fixed (v0.170.1)
- **Tout prefab était enregistré VIDE** (nœuds sans maillage ni lumière ni script) : son gabarit est
  un clone détaché dont les composants sont des objets nus, que la sérialisation écartait. Ils
  sont désormais écrits. Symptôme : instances invisibles et intouchables après rechargement ou en
  jeu (avatars du multijoueur). Voir docs/KNOWN_ISSUES.md.

Les correctifs v0.169.1 → v0.169.4 sont décrits dans `v0.169.0.md`.
