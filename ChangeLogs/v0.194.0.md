# v0.194.0 — Steam : succès, statistiques, Steam Cloud et Steam Input

## Ajouté

- **`api.steam`** (`js/steam-bridge.js`, partagé éditeur / jeu publié) : `available()`,
  `unlockAchievement(id)`, `isAchievementUnlocked(id)`, `clearAchievement(id)`, `setStat` /
  `getStat` / `addStat` (statistiques entières), `playerName()`, `language()`, `onDeck()` et
  `controller()` (type de manette vu par Steam Input, pour afficher les bons glyphes). **Tout est
  inerte hors Steam** — l'éditeur, un navigateur, ou l'application lancée sans le client : un
  script écrit pour Steam tourne partout.
- **Steam Cloud** : `api.save` / `api.load` / `api.clearSave` écrivent dans `localStorage` **et**,
  dans l'application de bureau, dans un fichier `jeu3d-<emplacement>.json` (Steam Cloud s'il est
  activé, toujours aussi dans le profil de l'utilisateur). À la lecture la copie du compte prime ;
  sans copie, on retombe sur `localStorage` — une partie d'avant l'export n'est pas perdue.
- **Steam Input, en complément de la manette** : les actions du projet sont déclarées à Steam
  (`steam/game_actions.vdf` et `steam_input.json`, engendrés à l'export bureau depuis la table
  d'entrées) ; l'action Steam `jump` rend vraie l'action `jump` du projet (touche `steam:jump`,
  liée d'office par `actionActive`), et les sticks `Move` / `Look` alimentent les axes nommés avec
  la même zone morte. La manette « Xbox virtuelle » de Steam continue de passer par l'API Gamepad.
- **Export bureau** : `steamworks.js` entre dans `package.json` (avec `asarUnpack`), `main.js`
  l'initialise dans un `try` (le jeu démarre sans Steam), active l'overlay, relaie les succès, les
  statistiques (envoyées à Steam par paquets) et Steam Input ; `steam_appid.txt` vaut `480`
  (application de test) ; le LISEZMOI explique les cinq étapes côté Steamworks.

## Modifié

- Le pont `window.bureau` expose désormais aussi `steam` et `cloud` (`test/build-bureau.test.mjs`
  fixe la liste des clés). Chaque message venu de la page est vérifié : cadre `jeu://` seulement,
  noms de succès / statistiques / fichiers par liste blanche.
- Plafond de `game-runtime.js` relevé de 2 lignes (4852) : l'import de `js/steam-bridge.js` et
  l'entrée `api.steam` ; la logique vit dans le module partagé.

## Vérifié, et ce qui ne l'est pas

Les tests (`test/steam.test.mjs`) couvrent le pont, l'inertie hors Steam, les sauvegardes, le VDF
et la conversion Steam Input → touches et axes. Le SDK est natif : **rien n'a été essayé contre un
vrai client Steam** — à faire avec l'identifiant de test 480 avant de brancher le vrai.
