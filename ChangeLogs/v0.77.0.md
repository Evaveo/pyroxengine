# v0.77.0 — 2026-08-21

**Un script ne pouvait afficher aucun texte dans l'interface du jeu.**

`data-bind` faisait `el.value = valeur` quel que soit l'élément visé. Sur un `<div>`, cela pose une
propriété JavaScript et rien d'autre : **aucune erreur, et rien à l'écran**. Le seul rendu possible
depuis un script était donc un champ de saisie — ce que personne n'écrit pour afficher un score, un
niveau ou un compte à rebours.

Encore la forme qui revient :

> le système existe, et aucun chemin n'y mène depuis un script.

Trouvé en construisant un jeu : le niveau, le nombre de cubes en jeu et l'objectif étaient tous
calculés, tous écrits dans `valeurs`, et le joueur ne voyait rien.

Désormais, un élément qui **n'est pas** un champ (`INPUT`, `TEXTAREA`, `SELECT`) reçoit son
`textContent`. Les champs gardent exactement leur comportement d'avant — écrire le texte d'un
`<input>` le rendrait non modifiable, et une case à cocher se remplirait du mot « true ».

`js/ui-jeu.js` est partagé par l'éditeur et le jeu publié : un seul correctif couvre les deux.

## Tests

**825 verts.** Six mutations sur ce chantier, base verte vérifiée avant et après, toutes tuées.

La garde **exécute** la liaison sur de vrais objets plutôt que de chercher un nom dans la source.
Elle couvre les deux sens (élément de texte / champ de saisie), la case à cocher, la clé absente —
qui écrirait « undefined » — et le **zéro** : `if(!valeurs[cle]) return` est le raccourci naturel,
et il ferait disparaître un score de 0.
