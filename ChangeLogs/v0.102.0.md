# v0.102.0 — l'éditeur de shader s'aligne sur Shader Graph

Passe complète sur l'éditeur nodal (`shader-graph-editor.js`) et sur le format de nœuds qu'il
pilote (`shader-graph.js`). La référence est le **Shader Graph d'Unity** : mêmes noms de nœuds,
même arborescence de catégories, mêmes blocs sur le Master, mêmes gestes.

## Ajouté

- **Le Master a ses deux blocs, Vertex et Fragment**, aux libellés d'Unity :
  - **Vertex** — `Position` (→ `positionNode`) : brancher un bruit ou un Time dessus **déforme
    réellement le maillage**. Présent aussi en Unlit : déplacer des sommets n'a rien à voir avec
    l'éclairage.
  - **Fragment** — `Base Color`, `Normal (Tangent Space)`, `Metallic`, **`Smoothness`**,
    `Emission`, **`Ambient Occlusion`**, `Alpha`, **`Alpha Clip Threshold`**.
  - `Smoothness` porte la convention d'Unity (1 = lisse) et est **inversé** au branchement, three
    raisonnant en rugosité. L'ancienne clé `roughness` reste acceptée telle quelle, sans
    inversion, et ne s'affiche que si un graphe s'en sert encore : aucun graphe ne change d'aspect.
- **Une troisième cible, `Lit (Physical)`** (`MeshPhysicalNodeMaterial`), qui ouvre les couches
  que le PBR standard n'a pas : `Coat Mask`, `Coat Smoothness`, `Sheen Color`, `Sheen Roughness`,
  `Iridescence` (+ épaisseur), `Transmission`, `Thickness`, `Index Of Refraction`,
  `Specular Color`, `Anisotropy`.
- **Les nœuds Vector prennent des entrées.** `Vector 2`, `Vector 3` et le nouveau `Vector 4` ont
  une **pastille par composante** (X, Y, Z, W), branchable, avec le champ inline tant que rien
  n'y est branché — exactement le comportement d'Unity.
- **Des ports partout où Shader Graph en a**, là où l'éditeur n'offrait qu'un champ figé :
  `Tiling And Offset` (Tuile, Décalage), `Rotate` (Angle, Centre), `Simple Noise`,
  `Fractal Noise`, `Voronoi` (Échelle, Désordre), `Cell Noise`, `Checkerboard` (Échelle),
  `Clamp` (Min, Max), `Remap` (ses quatre bornes).
- **Vingt-huit nœuds de plus**, tous aux noms et catégories d'Unity :
  - *Input / Geometry* : `Tangent Vector`, `Vertex Color`, `View Direction`, et l'espace **Vue**
    sur `Position` ;
  - *Artistic / Adjustment* : `Saturation`, `Hue`, `Vibrance`, `Posterize` ;
    *Artistic / Blend* : `Blend` (Overlay, Screen, Burn, Dodge) ;
  - *Math / Vector* : **`Fresnel Effect`**, `Reflection` ;
    *Math / Advanced* : `Exponential`, `Logarithm`, `Log Base 2`, `Reciprocal Square Root` ;
    *Math / Trigonometry* : `Arccosine`, `Arcsine`, `Arctangent`, `Degrees To Radians`,
    `Radians To Degrees` ; *Math / Round* : `Truncate` ;
    *Math / Derivative* : `DDX`, `DDY`, `DDXY` ;
  - *Channel* : `Swizzle` ; *UV* : `Spherize` ; *Utility / Logic* : `Is Front Face`.
- **Un widget inline vec2** (X/Y sur la ligne du port) et le nœud `Vector 2` qui le porte.
- **Le blackboard d'Unity, pour de vrai.** Les propriétés ne sont plus des nœuds : elles vivent
  dans `asset.properties`, indépendamment du plan.
  - leur **valeur par défaut s'édite dans la liste**, à un seul endroit, et plus sur un nœud ;
  - on **glisse une propriété sur le graphe** pour l'y lire, **autant de fois qu'on veut** —
    chaque nœud posé n'est qu'un renvoi (`property.ref`) vers la même entrée ;
  - une propriété peut exister **sans être posée** sur le plan, et reste exposée au matériau ;
  - les noms restent uniques (c'est la clé lue par le matériau instance), et supprimer une
    propriété emporte ses renvois.
  - Les anciens nœuds `param.*` sont **convertis à la première ouverture** du graphe : deux
    nœuds de même nom et même type — qui désignaient déjà la même propriété côté matériau —
    fusionnent en une entrée unique avec deux renvois.
- **Le code TSL et le graphe sont la même chose, dans les deux sens.** Le panneau `</> Code`
  n'est plus un miroir en lecture seule, et surtout pas une surcouche qui « prendrait le
  dessus » : c'est l'autre écriture du même graphe.
  - **Graphe → code** : le texte suit le plan à chaque modification, comme avant.
  - **Code → graphe** : « Appliquer au graphe » **relit le texte et repose les nœuds, les liens
    et les sorties** qu'il décrit. Écrire `positionLocal.add(normalLocal.mul(bruit))` pose trois
    nœuds branchés ; il n'y a jamais deux vérités.
  - L'aller-retour atteint son **point fixe dès le premier passage** : le texte régénéré après
    application est identique au texte appliqué (un test le vérifie sur un graphe complet).
    Une valeur tapée sur un port redevient une valeur inline, et l'échelle d'un bruit redevient
    son port — pas un `Multiply` de plus à chaque tour.
  - **Le blackboard est partagé par les deux vues.** Écrire `graph.property('Vitesse', 0.5)`
    dans le code **crée la propriété** si elle n'existe pas encore, son type déduit de la valeur
    (nombre → Float, `'#8fd8ff'` → Color, `vec3(x, y, z)` → Vector 3) ; `graph.sample('Diffuse', uv())`
    pour une texture. Une propriété que le graphe ne lit encore nulle part est déclarée en tête
    du texte, donc visible et modifiable des deux côtés.
    Le panneau reste **propriétaire de la valeur** : réappliquer un code portant un autre défaut
    ne réécrit pas ce qui a été réglé à la main. Et le code peut **ajouter** une propriété, jamais
    en supprimer — supprimer reste un geste explicite dans le panneau.
  - Une propriété s'écrit `graph.property('nom', défaut)`, une texture `graph.texture('idAsset')` :
    lisible, exécutable, et relisible. Le code ne fige plus le **défaut** d'une propriété comme
    le faisait l'ancien `float(1) // propriété « speed »`.
  - Un terme inconnu est **refusé en nommant la ligne**, sans toucher au graphe : reconstruire
    à moitié serait pire que ne rien reconstruire.
  - **La cible est dans le code** : `material.target = 'physical';`. Coller un shader Physical
    dans un graphe resté en Lit le fait basculer tout seul, au lieu de refuser ses onze couches.
    Et si la ligne manque, le refus nomme la cible qui possède le slot.
  - Un swizzle s'écrit sans parenthèses (`positionLocal.y`), la forme que le générateur produit
    lui-même et celle qu'on écrit naturellement.
  - Appliquer rend EXPLICITE ce que le texte ne peut pas distinguer : un port laissé à son
    défaut et un port branché sur la même valeur s'écrivent pareil, donc le second passage pose
    le nœud. Appliquer une seconde fois ne bouge plus rien — un test le vérifie.
  - Deux nœuds composites se relisent sous leur forme développée (`Tiling And Offset` en
    Multiply + Add, `Blend` en Blend + Lerp) : même rendu, plan un cran plus explicite.
- **Un filtre « Shaders » dans la vue**, à côté de Fil de fer / Ombres / Textures (et dans le
  menu Affichage). Coupé, les objets portant un matériau à graphe reviennent à un PBR neutre :
  on voit d'un coup d'œil lesquels en portent un, et on compare avant/après sans rien démonter.
  Le matériau du graphe est mis de côté tel quel, pas reconstruit — ses textures et les
  propriétés du matériau instance sont retrouvées intactes.

## Modifié

- **Le canvas nodal ne défile plus, il se déplace.** Le plan était une zone de 2400 × 1400 px
  avec des barres de défilement, et le déplacement butait sur ses bords. C'est maintenant une
  **transformation** : plus de barre, plus de butée, coordonnées négatives admises. **Molette** =
  déplacement (Maj pour l'axe opposé), **Ctrl/⌘ + molette** = zoom centré sur le curseur, molette
  enfoncée = glisser.
- **Les ports sont typés, et le typage filtre les branchements.** Chaque port déclare `float`,
  `vec2`, `vec3`, `vec4` ou `dynamic` — ce dernier pour les opérateurs comme `Multiply`, dont le
  type **remonte** de ce qui les alimente. Pendant un tirage, seules les pastilles où le fil a un
  sens s'allument ; un lâcher sur un port incompatible le **dit** dans la barre d'état au lieu de
  ne rien faire. La règle suit TSL : un scalaire se diffuse sur n'importe quel vecteur, un vec4
  se lit comme un vec3 (une texture sur une couleur), le reste est refusé. La pastille porte la
  couleur de son type.
- **Les libellés des ports passent en français** (`Tuile`, `Décalage`, `Échelle`, `Seuil`,
  `Puissance`…), les clés du format restant en anglais.

## Corrigé

- **La valeur tapée sur un port non branché n'était pas enregistrée.** Le champ était émis avec
  le préfixe `entree:` et relu avec `input:` : au lieu de créer la constante attendue, la saisie
  écrivait un param fantôme portant le nom de l'entrée, sans aucun effet sur le rendu.
- **Tiling And Offset et Rotate ne lisaient aucun de leurs champs.** L'éditeur écrivait
  `tuileX`/`decalageX`/`centreX`, le rendu lisait `tileX`/`offsetX`/`centerX` — reliquat de la
  migration des noms vers l'anglais. Tuiler une texture ne changeait strictement rien à l'image.
- **Le champ d'une valeur inline disparaissait dès qu'on la changeait.** Taper une valeur sur
  un port crée en coulisse un nœud constante `__auto` — donc un lien — et le champ n'était
  affiché que sur un port *sans* lien : il s'évanouissait au premier changement, sans moyen de
  corriger la valeur qu'on venait de saisir. Un port piloté par un nœud `__auto` est désormais
  traité comme le port libre qu'il est, et garde son champ.
- **Les propriétés créées se perdaient d'une ouverture à l'autre.** Rouvrir un graphe alors que
  la fenêtre externe est déjà ouverte ne recharge pas la page : l'éditeur est simplement rejoué.
  Ses écouteurs posés sur `document` (déplacement, relâchement, clavier), eux, survivaient à
  l'ancienne instance — chacun fermé sur **son** état. Le moindre geste réveillait alors
  l'instance périmée, dont la sauvegarde réécrivait l'asset avec un état d'avant. Un jeton de
  session neutralise définitivement l'instance remplacée, et l'aperçu de la précédente est
  démonté (son `WebGPURenderer` pointait de toute façon sur un canvas retiré de la page — la
  fuite de contexte GPU disparaît avec).
- **Le code généré ne compilait pas dès qu'une propriété y figurait.** La note
  `// propriété « … »` était écrite en fin de ligne, donc le point-virgule ajouté juste après
  tombait **dans** le commentaire et la ligne suivante s'y retrouvait collée. C'est un
  commentaire de bloc, en tête d'expression, désormais — et un test compile le code produit
  pour que la fonctionnalité « piloter le rendu par ce code » garde un sens.
- **Un scalaire branché sur `Position` (Vertex) faisait « disparaître » le modèle** sans un
  mot : un bruit (float) diffusé sur un vec3 pose (n, n, n) à chaque sommet, et tout le
  maillage s'écrase sur la diagonale. `Position` et `Normal` refusent maintenant une source
  scalaire, et le refus **dit par quoi commencer** (partir du nœud `Position` et y ajouter son
  déplacement, par exemple `Normal Vector × bruit`).
- **Le jeu exporté perdait le blackboard et le code TSL** : le runtime ne recopiait que
  `nodes`/`links`/`outputs` d'un `graphShader`. Un matériau publié n'y retrouvait donc ni ses
  propriétés ni le code qui pilote son rendu.
- **Les câbles avaient disparu.** La nappe SVG, ramenée à une taille nulle en `overflow:visible`
  lors du passage au plan transformé, ne peignait plus rien. Elle couvre désormais une grande
  surface décalée, et les câbles sont tracés dans un groupe qui la recentre — les coordonnées
  négatives, désormais possibles, y sont comprises.

Les graphes existants sont lus tels quels : un ancien param (`tileX`, `angle`, `scale`,
`desordre`, `eMin`, `x`/`y`/`z`…) sert désormais de **valeur par défaut du port** correspondant.
Aucun graphe ne change de rendu, aucune migration de schéma n'est nécessaire.
