# v0.193.1 — Ouverture d'un dossier de projet : accès en écriture demandé dès le sélecteur

## Corrigé

- **« Erreur lors du chargement du projet : Failed to execute 'getFileHandle'… The request is not
  allowed by the user agent »** à l'ouverture d'un projet dossier (ex. Donjons). Le sélecteur de
  dossier rendait un handle en lecture seule ; l'écriture du verrou multi-onglet
  (`.editeur-lock.json`), faite après le scan du dossier et donc sans geste utilisateur, était
  refusée. `openFolderProject` demande désormais `mode: 'readwrite'` dès le sélecteur.

- **Aides d'édition dessinées DERRIÈRE les tuiles et les images 2D** : la grille, les icônes et
  repères de lumière/caméra, le contour du collider (3D et `Collider2D`), les volumes de
  post-traitement, les boîtes de sonde, le squelette et le cadre du pinceau de tuiles passaient sous
  tout sprite. Les sprites sont transparents, sans test de profondeur, et classés par `renderOrder`
  (jusqu'à plusieurs milliers) ; une aide opaque était recouverte par la file transparente entière,
  et une aide à `renderOrder` 999 passait sous les calques supérieurs. Nouveau
  `js/editor-overlay.js` : `liftOverlay` met l'aide dans la file transparente avec un rang au-dessus
  de tout sprite (1 000 000). Le gizmo de transformation, déjà à `Infinity`, n'était pas concerné.
