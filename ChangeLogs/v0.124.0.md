# v0.124.0 — Le script d'un objet RÉFÉRENCE son asset

## Changé

- **Le composant `ScriptJS` référence son asset script au lieu d'en copier le code**
  (`moteur/js/components/component-script.js`, `moteur/js/assets.js:attachScriptAsset`). Un
  glisser-déposer écrivait `{code: asset.code}` sur l'objet : l'asset du panneau Projet n'était
  qu'un presse-papier. Conséquences, toutes les trois du même défaut :
    · éditer l'asset ensuite ne changeait AUCUN objet déjà servi ;
    · éditer le script d'un objet ne remontait pas à l'asset ;
    · deux objets nés du même script divergeaient sans que rien ne le signale.
  L'entrée sérialisée passe de `{code, active, values}` à `{scriptId, active, values}` : le
  composant porte l'identité (comme un MonoBehaviour tient son GUID) et les variables `@expose`,
  qui sont bien un réglage d'instance. **Il n'y a pas d'override local** — éditer l'asset se voit
  sur toutes ses instances, c'est le point.
- **Un seul éditeur de code** (`moteur/js/scripts.js`). `openEditorScript` ouvrait une fenêtre sur
  le code de l'INSTANCE pendant qu'`openEditorScriptAsset` en ouvrait une autre sur celui de
  l'asset : deux fenêtres, deux textes, aucun lien. La première ne fait plus que router vers la
  seconde ; ses appelants (double-clic sur une erreur de console, bouton « Éditer » de
  l'inspecteur) sont inchangés.
- **Le jeu publié résout la référence lui aussi** (`moteur/js/game-runtime.js`). Les assets script
  entrent dans `assetsById` — le commentaire « ils ne servent qu'à l'édition » était vrai tant que
  chaque composant portait une copie du code. Même format des deux côtés, pas de code inline
  recréé au build.
- **Le copilote crée un asset au lieu d'écrire du code sur l'objet** (`moteur/js/copilot.js`).
  `attach_script` fabrique un asset script (nouveau `newAssetScript`, la création sans ouvrir de
  fenêtre) puis le référence ; `replace_script` corrige l'asset, et refuse explicitement une
  entrée qui ne référence rien plutôt que d'écrire un `code` que plus personne ne lit.

## Ajouté

- **`⚠ manquant` sur le composant Script** (`moteur/js/ui/panels-components.js`) — le champ disait
  « (vide) », ce qui ne distinguait pas un script vide d'un script INTROUVABLE. Un objet qui
  n'exécute plus rien doit se lire sur le composant lui-même.
- **La suppression d'un asset script dit combien d'objets elle rend muets** (`moteur/js/
  assets.js`). Depuis que la référence existe, la croix du panneau Projet arrête du gameplay
  ailleurs dans la scène ; Ctrl+Z reste la sortie.
- **`codeOfScriptEntry` / `holdersOfScriptAsset`** (`moteur/js/scripts.js`) — la résolution en un
  seul endroit, et la liste des porteurs d'un asset. Miroir runtime : `rtCodeOfScriptEntry`.
- **`moteur/test/script-asset-reference.test.mjs`** — quatre tests sur le contrat : deux objets
  suivent le même asset quand il change, `serialize()` n'écrit jamais de `code`, un asset supprimé
  rend le composant manquant sans planter ni code fantôme, et les deux résolveurs (éditeur et
  runtime publié) s'accordent sur une référence absente ou cassée.

## Corrigé

- **`api.data(name)` prévient quand deux tables portent le même nom** (`moteur/js/scripts.js`).
  La référence est par nom — c'est assumé, un script écrit à la main ne peut pas porter un id —
  mais un nom n'est pas unique : deux homonymes, et le script lisait la première du tableau en
  silence. Symptôme observable : des statistiques « qui ne changent pas » quand on édite l'autre.

## Migration

**Aucune migration automatique, par décision.** Une entrée d'un projet antérieur n'a pas de
`scriptId` : son composant est posé quand même et s'affiche « ⚠ manquant », son ancien code reste
dans le fichier mais n'est plus exécuté. Les références se réattachent à la main, par
glisser-déposer du script depuis le panneau Projet.

## Audit — les autres composants référencent DÉJÀ

Vérification des 23 composants et de tous les points d'attache : `ScriptJS` était le seul à copier
du contenu d'asset. Déjà par référence : `material` (`userData.materialId`, avec matériau inline
assumé), `texture` (`texAsset`), `sprite` (`spriteId`), `animator` (`assetId`), `animation`,
`documentUI`/`sheetStyle` (`documentUIId`, `sheetStyleIds`), `tilePalette` (`paletteId`),
`postProfile` (`profileId`), `graphShader` (`shaderId`), `audio` (`userData.audio.asset` — ses
volume/loop copiés à l'attache sont des réglages d'instance, comme dans Unity), `prefab`
(`prefabId`) et `model` (`assetId`).
