# v0.165.0 — le texte du jeu, traduit

Deuxième des trois manques rédhibitoires pour un studio. Il ne s'agit pas de l'interface de
l'éditeur, qui reste en français : il s'agit du texte que le **joueur** lit — menus, dialogues,
objectifs, fins de partie.

## La règle qui tient tout le fichier

**Une clé manquante se voit.** Elle rend la clé elle-même : `menu.start` s'affiche en toutes
lettres à l'écran, et l'on sait immédiatement quoi traduire.

C'est le contraire de ce que font beaucoup de moteurs — rendre une chaîne vide — et ce n'est pas
un détail de confort. Un bouton vide passe les tests, passe la relecture, et se découvre en
production. Un bouton qui affiche `menu.start` se corrige le jour où on le voit.

Les clés manquantes sont aussi **retenues** (`api.t` les collecte, `missingKeys()` les rend) et
signalées **une seule fois** en console. Une seule : à soixante images par seconde, un
avertissement par image est un avertissement qu'on désactive — et on désactive alors aussi celui
qui comptait.

Même principe pour les paramètres : `'Score : {n}'` sans valeur laisse `{n}` visible. Le
remplacer par du vide donnerait « Score : », qu'on lit comme une faute de traduction alors que
c'est le script qui a oublié de passer le nombre.

## Le choix de la langue

Trois sources, dans cet ordre : ce que le joueur a choisi lors d'une partie précédente, ce que
son navigateur annonce, la langue par défaut du projet.

`en-GB` tombe sur `en` quand `en-GB` n'existe pas — sans cette règle, la moitié du monde
anglophone se verrait servir du français. Et le code **générique** prime sur une autre variante
régionale : un projet qui fournit `en` et `en-US` sert `en` à un joueur britannique, pas
l'américain. Cette dernière règle a été ajoutée après coup — une mutation du code court restait
muette, et le test qui manquait a révélé que les deux branches n'étaient pas distinguées.

## Ce que ça donne côté auteur

```js
api.t('menu.start')              // « Commencer » ou « Start »
api.t('hud.score', {n: 42})      // « Score : 42 »
api.locale()                     // 'fr'
api.locales()                    // ['fr', 'en'] — de quoi construire un menu de choix
api.setLocale('en')              // false si le projet ne fournit pas l'anglais
```

Dans le HTML d'interface : `<button data-t="menu.start">`. Les traductions sont appliquées
**avant** les valeurs liées par script (`data-bind`), et l'ordre est un contrat — un élément qui
porte les deux doit finir par la valeur, sinon le score s'effacerait à chaque image et l'on
chercherait la faute dans le script.

`setLocale` **refuse** une langue que le projet ne fournit pas, et le dit. L'accepter viderait
tout le texte du jeu, et l'on chercherait la panne dans les traductions.

## Où vit la table, et comment on la remplit

Dans les réglages du **projet** (`settings.locales`), comme la table d'entrées : elle voyage
avec le projet, part dans le build, se relit dans l'éditeur. Pas de nouveau genre d'asset.

Le panneau Paramètres du projet gagne une section **Langues du jeu** : les codes de langue, la
langue par défaut, celle qu'on est en train de traduire, et la liste des clés avec leur texte.
La langue éditée est un état d'**éditeur** et non de projet — elle ne voyage pas avec le
fichier, et deux personnes peuvent traduire deux langues sans se marcher dessus.

La liste montre **toutes** les clés, toutes langues confondues : une clé traduite en français
reste visible quand on édite l'anglais, sans quoi on ne saurait pas ce qu'il reste à faire.
Retirer une clé la retire de **toutes** les langues — l'ôter d'une seule laisserait une
traduction orpheline que plus rien n'afficherait.

`exportLocaleJson` / `importLocaleJson` donnent à un traducteur le fichier `.json` d'une langue
et relisent ce qu'il rend. Un fichier abîmé — une virgule de trop, un tableau au lieu d'un objet
— est **refusé sans écraser la table** : écraser perdrait le travail déjà fait. Un fichier à
demi juste est repris pour ce qu'il a de bon.

## Les gardes

`moteur/test/localisation.test.mjs` — vingt-deux tests couvrant les cinq familles de pannes
silencieuses : la clé rendue vide, l'étiquette régionale, le paramètre oublié, la langue
inexistante, et la **divergence éditeur / jeu publié** (si l'un des deux moteurs n'installe pas
la table, son interface affiche les clés brutes, et l'écart ne se voit qu'après l'export).

**Dix mutations passées, dix attrapées** — la dixième après avoir ajouté le test qui manquait.

Vérifié dans le vrai éditeur : `en-GB` choisit `en`, `api.t('hud.score', {n: 42})` rend
« Score: 42 », une clé absente s'affiche en toutes lettres et entre dans la liste des
manquantes, et `data-t` remplit un vrai élément du DOM.
