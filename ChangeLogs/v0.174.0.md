# v0.174.0 — le copilote pose son propre pixel art

Constaté en faisant construire un jeu façon Terraria par un agent MCP : faute d'outil pour
importer une image, il dessinait tout son pixel art dans un script, au lancement (plusieurs
centaines de canvas refaits à chaque démarrage, invisibles dans le panneau Projet), et il ne
pouvait pas supprimer une scène devenue inutile.

## Added
- Outil copilote/MCP `import_image` (domaine `render`) : importe un PNG donné en base64 comme
  asset texture (filtrage au plus proche, sans mipmaps), rangé dans `Textures` par défaut, et le
  découpe en planche de sprite si `cell` est donné. Réimporter sous le même nom remplace l'image.
- API de script `api.image(nom)` (éditeur et jeu publié) : l'élément image d'un asset texture,
  pour un script qui dessine lui-même dans un canvas d'interface.
- `manage_scenes` : actions `rename` (`newName`) et `delete` (sans boîte `confirm()`, qui
  bloquait un appel MCP ; le projet garde toujours au moins une scène).

## Changed
- Invite du copilote (règles MCP) : les sprites, tuiles, icônes et fonds sont des ASSETS, jamais
  générés par un script au lancement ; quand un outil manque, le dire au lieu de le contourner.

  `globalThis.ENGINE_TRIMMED_MODULES`, et `warnOnceMissing` se tait pour ces modules.
