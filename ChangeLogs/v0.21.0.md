# v0.21.0 — 2026-08-06

Fondation pour le futur éditeur nodal TSL (matériaux) : le moteur bascule sur
`WebGPURenderer` (repli WebGL2 automatique intégré à three.js), et les deux pipelines qui
utilisaient des shaders GLSL bruts (post-traitement, particules) sont réécrits en noeuds
TSL, dans l'éditeur et dans les builds exportés.

## Ajouté

- Pont ESM `js/render-webgpu-bridge.mjs` (`<script type="module">`) : expose
  `WebGPURenderer`/TSL sur `window.THREE`/`window.TSL` — three.js ne publie plus de build
  UMD/global pour ces modules depuis ~r160. N'écrase jamais une classe déjà présente dans
  le `THREE` classique (`vendor/three.min.js`, qui garde ses addons GLTFLoader/FBXLoader/
  TransformControls).
- Vendoring `moteur/vendor-esm/` (paquet npm `three` 0.185.0, builds ESM `three.core`/
  `three.webgpu`/`three.tsl`), embarqué aussi dans le ZIP des builds exportés.

## Modifié

- `scene.js` (éditeur) et `runtime-jeu.js` (jeu publié) : `WebGLRenderer` → `WebGPURenderer`.
- `postprod.js`/`particules.js` (et leurs copies indépendantes dans `runtime-jeu.js`) :
  les `ShaderMaterial` GLSL (bloom, flou, tonemap/vignette/grain, FXAA, sprites de
  particules) deviennent des `NodeMaterial`/`PointsNodeMaterial` avec des graphes TSL —
  WebGPURenderer n'exécute pas de GLSL brut. Réglages et format sérialisé (`env.post`,
  `userData.part`) inchangés.
- Tous les `<script src="js/...">` d'`editeur.html` (et du HTML généré par `build.js`)
  passent en `defer`, pour s'exécuter dans le même ordre relatif que le pont ESM (toujours
  différé). `lint-ordre-chargement.mjs` mis à jour en conséquence.

## Notes

Le rendu WebGPU/TSL n'est pas simulable par le harnais de test `node:vm` du projet (pas de
WebGPU en Node) — **le portage TSL de `postprod.js`/`particules.js`/leurs copies dans
`runtime-jeu.js` n'a pu être vérifié que par relecture, pas par exécution réelle en
navigateur.** Vérification manuelle indispensable avant de considérer ce lot stable :
rendu de base, bloom, FXAA, tonemap, vignette/grain, particules, et le pont ESM lui-même
(l'ordre `defer`/module, la fusion `THREE` classique + webgpu). Voir
`docs/superpowers/specs/2026-08-06-fondation-webgpu-tsl-design.md`.
