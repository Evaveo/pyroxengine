# v0.72.0 — 2026-08-18

**Le code des scripts s'annule aussi.** Ce n'est pas la suite logique des deux versions
précédentes : c'est une **réparation**. Le défaut était déjà là, et il faisait perdre du code.

## Ce qui se passait vraiment

Le code d'un script d'objet vit dans `userData.scripts`, que `serialiserObjet` photographie **depuis
toujours**. Mais la fenêtre d'édition n'empilait aucun pas — un commentaire l'expliquait :

> Pas de `pousserHistorique()` ici : la frappe est enregistrée en continu (debounce de 300 ms), et un
> instantané par salve de touches noierait la pile d'annulation.

Le constat était juste. La conclusion, non. Sans pas dédié, un <kbd>Ctrl</kbd> + <kbd>Z</kbd> venu
d'un geste **antérieur** remontait à un instantané pris avant l'édition et rendait l'ancien code.

**Mesuré dans le navigateur, avant correction** : `// C1 du code TAPÉ` redevenait `// C0` en deux
<kbd>Ctrl</kbd> + <kbd>Z</kbd>, sans qu'aucun pas ne lui corresponde.

Le cas le plus dur est celui sans geste intermédiaire : on édite un script, on presse
<kbd>Ctrl</kbd> + <kbd>Z</kbd> — et on annulait l'action précédente **en emportant le code avec
elle**, en un seul geste.

## Un pas par SESSION, pas par salve

La bonne granularité n'était ni « aucun pas » ni « un par salve » : c'est **un par session
d'édition**, posé à la première frappe qui change vraiment quelque chose — donc sur l'état d'**avant**
la session. <kbd>Ctrl</kbd> + <kbd>Z</kbd> rend alors le script tel qu'il était à l'ouverture de la
fenêtre.

Mesuré : quatre salves debouncées → **un** pas ; <kbd>Ctrl</kbd> + <kbd>Z</kbd> ne défait que
l'édition, la position de l'objet reste intacte ; <kbd>Ctrl</kbd> + <kbd>Y</kbd> rend le code.

La comparaison se fait **avant** l'écriture : un rappel qui renvoie le code inchangé n'empile rien,
sinon le premier <kbd>Ctrl</kbd> + <kbd>Z</kbd> n'aurait l'air de rien faire — le symptôme qu'on
corrige depuis trois versions.

Les deux chemins d'édition sont couverts : le script d'un **objet** et l'asset script du panneau
**Projet** (où le renommage dans la fenêtre externe compte aussi, n'ayant aucune prise de focus dans
le panneau pour le couvrir).

## Deux annulations qui ne se disputent pas

La zone d'édition est une vraie `<textarea>` : elle garde son annulation **native**, mot à mot. Et le
gestionnaire clavier de l'éditeur ignore déjà les champs de saisie, donc <kbd>Ctrl</kbd> + <kbd>Z</kbd>
dans le code n'atteint jamais la scène.

Les deux couches se complètent au lieu de se gêner — fine dans la fenêtre, par session depuis
l'éditeur — et elles ne sont même pas dans la même fenêtre. L'aide le dit, parce que c'est ce qui
surprend : depuis l'éditeur on ne remonte pas mot à mot.

## L'historique est désormais complet

`CHAMPS_ASSET_HORS_HISTO` ne contient plus que de l'identité (`id`, `genre`), une URL transitoire
(`apercu`) et les poignées vivantes (`fichier`, `texture`, `buffer`…). Plus aucun champ de **données**
n'en est exclu.

Restent hors historique, et c'est documenté depuis longtemps : les opérations **disque** sur les
dossiers de projet, qui demandent une confirmation avant exécution.

## Tests

**743 verts.** **7 mutations, base verte vérifiée, toutes tuées** — la première remet exactement le
défaut mesuré.

Deux gardes de prose ont dû être refaites, et l'échec était le mien à chaque fois :

- la première cherchait le mot « session » dans la page — or il y apparaît **aussi** trente lignes
  plus bas à propos du copilote. Effacer toute l'explication laissait le test vert ;
- la seconde était une **disjonction** de trois formulations : chaque mutation n'en cassait qu'une
  branche, les deux autres continuant de matcher ailleurs.

Une garde sur de la prose ne peut pas être robuste au reformulage, et prétendre le contraire fabrique
un test qui ne mesure rien. Elle exige donc **une** formulation — la reformuler fait rougir le test,
ce qui est le bon moment pour relire. C'est exactement le contrat du système d'ancres de l'aide.

S'y ajoute une garde qui, elle, ne dépend d'aucune prose : la borne de la pile (**50**) est lue dans
`js/historique.js` et doit se retrouver dans la page. C'est elle qui explique pourquoi une rafale ne
peut pas empiler un pas par caractère.

Et une mutation a survécu avant d'être corrigée — pas la garde, la **mutation** : elle ne retirait que
le titre `<h3>` du grain, en laissant le texte dessous. Mesurer une garde demande de casser ce qu'elle
protège, pas ce qui l'entoure.
