# v0.186.0 — un catalogue de plugins, sur une page

Jusqu'ici, découvrir un plugin livré avec le moteur voulait dire ouvrir `moteur/exemples/` dans un
explorateur de fichiers, deviner à quoi servait `plugin-pont-mcp.js`, apprendre ses prérequis en
lisant son code — puis revenir dans l'éditeur installer le `.js`. Les trois plugins du dépôt
étaient donc, en pratique, invisibles pour qui ne lit pas le dépôt.

## Ce qui est ajouté

**`/editeur/plugins.html`** — une page servie à côté de l'éditeur, qui présente les plugins,
se filtre (recherche libre + catégories), annonce pour chacun **ce qu'il ajoute** et **ce qu'il
faut avoir avant de l'installer**, et l'installe en un clic.

Deux portes d'entrée, parce qu'elles ne servent pas au même moment :

- **Fichier → 🧩 Plugins → 🏪 Parcourir le catalogue…** — pour qui en cherche un et ne sait pas où regarder ;
- le bouton **« 🏪 Parcourir le catalogue… »** dans la modale Plugins — pour qui gère les siens.

C'est une **page**, pas une modale : elle se lit à côté de l'éditeur, elle garde ses filtres
pendant qu'on regarde la scène, et son URL s'envoie à quelqu'un. Ouverte seule, elle reste
entièrement lisible et propose le téléchargement du `.js` — une bannière dit lequel des deux cas
on est, au lieu de laisser un bouton sans effet.

## La page n'installe rien, et c'est le point

Installer un plugin veut dire **exécuter du code avec tous les droits de l'éditeur**. La page du
catalogue n'est pas l'éditeur.

Une page qui enverrait le JavaScript à installer ferait du canal un canal d'**exécution** : ce qui
franchirait les contrôles s'exécuterait tel quel dans l'éditeur. Elle envoie donc un **nom de
fichier**, et l'éditeur va lire lui-même `exemples/<nom>` — après avoir vérifié que ce nom figure
dans le catalogue **qu'il a chargé de son côté**. Le pire qu'un message forgé puisse obtenir est
l'installation d'un plugin déjà livré avec le moteur, et encore : derrière le `confirm()`
d'`installPlugin`, inchangé.

`installRequestFile()` (`js/plugin-catalog.js`) porte les trois verrous, et
`test/catalogue-plugins.test.mjs` **casse chacun séparément** — un verrou qu'on ne voit jamais
refuser n'a pas été mesuré :

1. la demande porte **le jeton que cet éditeur a tiré** en ouvrant cette page-là ;
2. l'origine est la nôtre ;
3. le fichier figure au catalogue, et porte un nom qui ne peut pas sortir de `exemples/`.

Mesuré, six mutations, six tests tombés : verrou du jeton retiré → « une demande sans le jeton de
CET éditeur est refusée » ; contrôle d'origine retiré → « une origine étrangère est refusée » ;
contrôle du catalogue remplacé par `return file` → « un fichier hors catalogue est refusé » ;
règle de nom réduite à `/\.js$/` → « un nom qui sortirait de `exemples/` est refusé » ; tirage
aléatoire du jeton retiré, puis lecture du fragment relâchée → « le jeton est tiré au hasard, et
il se relit dans le fragment ». Un test vérifie en plus, dans la source, que la page n'envoie
jamais de code et jamais vers `'*'`.

### Pourquoi un jeton, et pas `window.opener`

La première version liait la demande à la fenêtre ouverte par l'éditeur
(`event.source === gate.win`). **Mesuré dans un vrai navigateur** : le `window.open()` d'un volet
intégré rend une fenêtre **sans `opener`** — l'installation en un clic ne marchait simplement pas,
et sans une erreur. Un contrôle qui dépend de la sémantique des popups n'est pas un contrôle, c'est
un pari.

Le lien passe donc par un **jeton de 128 bits** tiré à chaque ouverture et transmis dans le
**fragment** de l'URL (`plugins.html#k=…`) : le fragment ne part pas au serveur, il n'entre pas
dans ses journaux d'accès, et une autre page de la même origine ne peut pas le lire. La page
l'efface de la barre d'adresse dès qu'elle l'a lu. Le canal est un `BroadcastChannel`, que le
navigateur borne déjà à l'origine — il n'a pas besoin d'`opener`. La comparaison des jetons est à
longueur constante.

## Le catalogue ne peut pas mentir

`exemples/catalogue.json` décrit les entrées. Le test le confronte au **dossier**, dans les deux
sens : un plugin livré sans entrée échoue, une entrée sans fichier échoue. Sans cela, un
« Installer » silencieusement mort, ou un plugin livré et introuvable.

Le nom d'installation est le **nom de fichier**, pas le titre : c'est celui que donne
l'installation manuelle d'un `.js`. Prendre le titre ferait cohabiter « Pont MCP » et
« plugin-pont-mcp » comme deux plugins distincts, avec leurs deux jeux d'extensions.

## Au passage — une garde qui ne regardait que trois pages

`test/ordre-feuilles.test.mjs` vérifie qu'aucune feuille de `css/` n'est oubliée. Sa liste de
pages était **écrite en dur** : `editor.html`, `help.html`, `hub.html`. Une feuille chargée par une
quatrième page passait donc pour orpheline, et ajouter une page obligeait à **modifier le test**
— c'est-à-dire à relâcher la garde pour faire passer du neuf. Elle lit maintenant toutes les
pages du dépôt, comme le test juste en dessous le faisait déjà pour la brèche symétrique.

## Vérifié

2 203 tests verts, et la chaîne complète jouée dans un vrai navigateur, éditeur et catalogue dans
deux onglets :

- les trois plugins s'affichent ; la recherche « blender » trouve le Studio, **dont le titre ne
  contient pas ce mot** ; les filtres de catégorie se cumulent avec la recherche ;
- une demande portant un **mauvais jeton** n'installe rien et ne déclenche même pas le
  `confirm()` — la sonde posée sur le canal montre le message reçu, et refusé à la porte ;
- avec le bon jeton, l'avertissement s'affiche (« Installer le plugin « plugin-pont-mcp » ? … tous
  les droits de l'éditeur »). **Refusé** → rien n'est installé et la page écrit « L'éditeur n'a pas
  installé ce plugin » : le rapport suit ce qui EST, pas ce qui a été demandé. **Accepté** → le
  plugin entre dans `Editor.plugins` et dans le `localStorage` sous `plugin-pont-mcp`, la carte
  passe « ✓ Installé », et après rechargement le menu **Extensions** du pont apparaît dans la
  barre.

La page annonce d'ailleurs « Installé — **rechargez l'éditeur** pour voir ses menus et ses
panneaux », et non « l'éditeur est à jour » : la barre de menus est construite au démarrage, la
seconde formule aurait été exacte pour un matériau et fausse pour un menu.
