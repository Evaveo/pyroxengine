# v0.148.0 — 2026-09-18

Déplier un modèle dans le panneau Projet montre **tout ce que le fichier contient** — maillages,
matériaux, clips, squelette — et pas seulement ses maillages.

## Ajouté

- **La flèche d'un modèle déplie ses quatre familles de contenu**, comme un FBX dans la fenêtre
  Project d'Unity :
  - les **maillages** (déjà là en v0.145.0) ;
  - les **matériaux du fichier**, un par emplacement — avec ce que le matériau déclare vraiment
    (couleur, émissif, opacité, double face, textures branchées) et **par quoi il est remplacé**
    dans le projet ;
  - les **clips** du fichier : durée, nombre de pistes, nombre d'os visés, et l'asset Animation
    qui le référence — ou son absence, qui explique pourquoi le clip n'est jouable nulle part ;
  - le **squelette** : os distincts, répétitions du fichier, racines, état de l'Avatar.
- Chaque vue est en **lecture seule** et le dit : ni bouton d'application, ni réglage. Les
  paramètres restent sur le fichier, un clic sur sa tile y ramène. C'est la séparation d'Unity, et
  ce qui la tient ici est que `a._sub` est une **vue** (`{kind, index}`), jamais un réglage — il ne
  se sérialise pas.
- **Un matériau que le chargeur n'a pas su traduire le dit maintenant dans le panneau.** FBXLoader
  ne fabrique que du Phong et du Lambert : un matériau **OpenPBR, Arnold ou Standard Surface**
  arrive donc sans rugosité ni métal, et jusqu'ici ça ne se lisait que dans un avertissement de
  console (`unknown material type "openPBRSurface". Defaulting to MeshPhongMaterial`). La vue du
  matériau l'explique et renvoie vers l'extraction, qui en fabrique un PBR propre.

## Compatibilité

Aucune migration, aucun réglage nouveau : c'est de la consultation.
