# v0.51.1 — 2026-08-12

**Le sélecteur de fichier arrive sur l'éditeur de machine à états.** Il existait pour les
scripts et les graphes de shader ; l'éditeur de machine à états était le seul des trois à en
être privé — et ce n'était pas un choix, juste ce que la fusion des deux chantiers avait laissé
en l'état.

## Ce que ça change

La fenêtre JSON d'une machine affiche désormais le bandeau avec la liste de toutes les machines
du projet. On passe de l'une à l'autre sans revenir chercher un objet dans la scène.

Concrètement, l'ouverture transmet maintenant ce que le bandeau attendait : `id`, `nom`,
`listeFichiers`, et le rappel de changement de fichier. Sans eux, la fenêtre se cachait le
bandeau toute seule, en silence.

## Le détail qui n'était pas évident

Au changement de machine, le nœud repris est celui **sélectionné**, pas celui d'origine. Le
nœud ne sert qu'à un seul effet de bord — arrêter le lecteur en cours, dont l'état courant peut
ne plus exister dans une machine qu'on vient de réécrire. Or la machine qu'on vient d'ouvrir n'a
aucune raison d'être celle que joue l'objet par lequel on est entré : garder l'ancien nœud
arrêterait le lecteur d'un personnage sans rapport.

## Mesures

Vérifié sur les deux moitiés, sur des machines réelles :

- **Côté éditeur** : l'ouverture transmet bien `id`, `nom`, les deux machines du projet dans
  `listeFichiers`, et le rappel de changement. Choisir l'autre machine rouvre sur le bon
  identifiant et envoie bien SON contenu.
- **Côté fenêtre externe** : le bandeau devient visible, les deux options sont là, la machine
  courante est sélectionnée, la zone JSON est en place et le message « aucun fichier de ce
  type » ne s'affiche pas.
- **Pas de contamination croisée** : enregistrer depuis la seconde machine écrit dans la
  seconde, et la première reste intacte.
- **Un JSON invalide n'écrit toujours rien** — la garde qui protège d'une machine à moitié
  tapée n'a pas bougé.

493 tests, inchangés : ce lot ne touche qu'un branchement d'interface.
