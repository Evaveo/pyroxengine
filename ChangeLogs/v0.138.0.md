# v0.138.0

## Ajouté — un exporteur en ligne de commande

```bash
node moteur/outils/exporter.mjs jeux/Chromelo --out /chemin/de/sortie
```

- Rend un **dossier prêt à héberger** (`index.html`, `data.js`, les modules du moteur), à
  déposer tel quel sur n'importe quel hébergeur statique, ou à ouvrir en double-cliquant
  `index.html` — tout passe par des balises `<script>`, il n'y a aucun `fetch` à servir.
- Sans `--out`, écrit dans `<projet>/web/` (ignoré par git : c'est un artefact daté).
- Aussi disponible en `npm run export -- ../jeux/Chromelo` depuis `moteur/`.

**Il ne recopie aucune logique de publication.** La table des modules (`BUILD_MODULES`), le
gabarit de `index.html` (`pageIndexBuild`), le choix des décodeurs (`decodersNeeded`) et
l'allègement (`trimmingBuild`) sont lus dans `js/build.js` et exécutés tels quels. Deux
publieurs qui divergent, c'est un jeu en ligne qui ne se comporte pas comme l'aperçu : il n'y a
qu'une source, et elle reste dans `js/`.

Le bouton « Exporter » de l'éditeur ne change pas. Il reste le bon outil pour essayer un jeu ;
celui-ci est là pour mettre en ligne et pour publier depuis un script, deux choses qu'un ZIP
téléchargé par le navigateur rend pénibles (et qui exigeaient d'ailleurs que l'éditeur soit
lui-même servi en http).

Un type d'asset que l'exporteur ne sait pas inliner **arrête l'export** en le nommant, au lieu
de publier un jeu auquel il manque une pièce en silence.

## Corrigé — plus rien n'était cliquable dans une interface écrite à la main

- La couche qui accueille les documents est en `pointer-events:none` (pour qu'un HUD plein écran
  ne bloque pas la scène 3D derrière), et **seule la classe `.ui-button`** réactivait les clics —
  une classe héritée de l'ancienne UI plate du moteur.
- Une interface reprise d'un prototype web, faite de `<button>` ordinaires, n'était donc
  **cliquable nulle part**. Pas une erreur, pas un avertissement : les événements ne partaient
  simplement jamais, et on cherchait le défaut dans son script, qui était juste.
- Le moteur pose maintenant ses propres règles de base dans chaque document :
  `a[href]`, `button`, `input`, `select`, `textarea`, `label`, `canvas`, `video`, `audio`,
  `summary`, `[data-event]`, `[data-bind]`, `[contenteditable]`, `[tabindex]` sont cliquables
  **sans qu'on ait à connaître quoi que ce soit**.
- Elles sont posées **avant** le CSS de l'auteur, qui peut donc toujours les contredire. La
  racine du document, elle, reste transparente aux clics : un HUD continue de laisser passer la
  souris dans ses zones vides, et un document qui est une page entière le déclare sur sa propre
  racine, comme sur le web.

## Corrigé — `@charset` mangeait la première règle d'une feuille de style

- Les at-rules **sans bloc** (`@charset`, `@import`, `@namespace`) finissent par un
  point-virgule. `scopeCss` les collait au sélecteur suivant, qui commençait alors par `@` : la
  règle qui suivait partait **non cantonnée** sur toute la page.
- Une feuille qui commence par `@charset "UTF-8";` — ce qui est courant — perdait donc sa
  première règle dans la nature.
