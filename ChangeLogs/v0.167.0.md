# v0.167.0 — une IA, locale ou non, qui pilote l'éditeur hébergé

L'éditeur sera servi par le web : il n'y aura plus de `bridge.mjs` sur le disque. Le pont MCP
passe donc par le cloud, sans rien à installer.

## Added
- **Relais MCP hébergé** (`cloud/`) : point MCP standard (Streamable HTTP) `POST /api/mcp`
  (jeton `Authorization: Bearer` ou URL `/api/mcp/t/<jeton>`), relayé à l'onglet de l'éditeur
  connecté par `/api/mcp/ws` (session du compte, un éditeur par compte).
- Jetons MCP par compte, révocables (`/api/mcp/jetons`), stockés hachés.
- Copilote → ⚙ → **Via le cloud** : « Connecter l'éditeur » (reconnexion auto), « Créer une URL
  pour mon IA » avec les commandes prêtes pour Claude (connecteur), Claude Code et une IA locale
  stdio (`npx -y mcp-remote <url>`).
- Le pont local (`moteur/outils/mcp-bridge/`) reste disponible, replié, pour le hors ligne.

## Fixed (v0.166.1)
- Envoi des fichiers sur le cloud refusé en 415 : le type `application/octet-stream` manquait.

## Changed (v0.167.1)
- Le Copilote IA devient un panneau dockable comme les autres (onglet de la colonne de droite
  par défaut, ⚙ et 🗑 dans la barre d'onglets).
- Relais MCP : plus de tentatives en boucle. Un serveur sans relais (404) arrête tout avec un
  message ; les autres échecs réessaient de 3 s à 30 s.
